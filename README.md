# medscope — 胸片阅片副驾

> **教育演示项目，非医疗器械。** 不用于临床诊断、不用于任何真实诊疗决策。
> 数据全部来自公开去标识数据集（NLM Open-i / Indiana University 胸片集），不接触任何真实患者数据。
> 系统只产出**报告草稿**，签发权永远在执业医师。

`medscope` 取自放射科真实术语 **second reader（第二读片者）**——这既是架构隐喻，也是定位声明：AI 是第二个读片的人，不是主诊医生。

---

## 这是什么

输入一张胸片 + 既往病历文本 + 检查申请单，输出一份**每句结论都挂着证据**的结构化报告草稿，外加一条独立的危急值告警通道。

**招牌是异质双读一裁**，直接搬自放射科真实的双读制 SOP：

- `reader_a` — 判别式 CNN（TorchXRayVision DenseNet-121），出**定量概率 + Grad-CAM 定位**
- `reader_b` — 生成式 VLM 看原图独立读片，能结合临床语境推理，但不给数值、不给定位
- 两者**失效模式正交**，所以分歧不是要抹平的噪声，而是「这张片上有一处需要人看」的精确指针
- 仲裁只在分歧项上花 LLM 预算；危急值走**旁路**，不等报告写完就告警

## 四道硬门

交付验收由 `medscope-eval` 把关，不过就 exit 非 0：

| 门 | 指标 |
|---|---|
| **G1 危急值零漏判** | 金标准集 recall = 1.0；误报只设软上限 |
| **G2 无证据不出句** | 结论句证据覆盖率 = 1.0，裸断言 = 0 |
| **G3 诊断口径红线** | 确诊/排除/处方措辞拦截率 = 1.0 + 免责声明存在率 = 1.0 |
| **G4 PHI 零泄漏** | 上云 payload 中 PHI 命中 = 0 |

**G1 的非对称是刻意的**：漏一例气胸可能致命，多报一例只花医生三十秒。所以召回是硬门、误报率只是软指标，两者不合并成 F1。

## 快速开始

```bash
python3.12 -m venv .venv                     # torch 在 3.14 上无可靠 wheel
.venv/bin/pip install -e ".[cv]"
PYTHONPATH=src .venv/bin/pytest -q           # 168 passed, 1 deselected
```

数据集（仓内已含 3 例样本切片，**克隆即可离线跑测试**）：

```bash
PYTHONPATH=src .venv/bin/python scripts/fetch_openi.py --image-bytes 20000000
```

完整图像包 1.36 GB、本地实测带宽约 379 KB/s，需一小时以上；`--image-bytes` 用 HTTP Range 只取前缀，20 MB 即可解出约 108 张完整 PNG。

## 诚实的局限

这一节记录的是**已知不成立的部分**。它不是待办清单的委婉说法，而是阅读本项目结论时必须一并知道的前提。

### G1 的实际覆盖窄于它的名字

`CRITICAL_LABELS` 有三个标签，但：

- **纵隔气肿**：`densenet121-res224-all` 的 18 类输出里**根本没有这个标签**，`reader_a` 结构上无法产出它。其召回只能依赖尚未接入的 VLM。
- 金标准集 53 例中，纵隔气肿**确证阳性只有 1 例**——全数据集 3955 份报告里仅 7 份提及，5 份是否定式、1 份是既往史。
- **大量胸腔积液**：模型输出 `Effusion` 不区分严重程度，「大量」这一临床判断由概率阈值近似，不是模型直接给出的。

保留纵隔气肿标签是刻意的：它在临床上就是危急值，为了让指标好看而删掉它，是**用重新定义标准来消灭局限**。

### 金标准集没有一例阳性能端到端跑

53 例全部依据报告文本 + MeSH 人工核对，但**确证阳性病例的图像都不在本地那 108 张里**。也就是说 G1 目前验证的是 `triage()` 的规则逻辑，不是「真实图像 → CNN → 告警」的完整链路。需要下载完整数据集后才能补上。

### PHI 脱敏不完备

`deid.py` 的规则由**手工枚举的形态清单**驱动，因此永远是现实的真子集——测试集的对抗性上限就是那份清单。开发过程中先后发现并修复了八类漏检（连写手机号、CJK 紧邻标识符、三字名与复姓、`+86` 前缀、间隔号音译名、点分日期、小写前缀……），每一次发现前测试都是全绿的。

已知仍不支持的形态记录在 `deid.py` 的模块 docstring 里（中文数字日期、带连字符的身份证、无上下文的裸数字串等）。**把它当作「对已发现的形态有效」，而不是「PHI-proof」。**

### 未接真实 DICOM

Open-i 的 DICOM 分发不可达，仓库只有 PNG。DICOM 标签白名单逻辑由**内存中合成的 `pydicom.Dataset`** 覆盖，未在真实 DICOM 文件上验证过。

### 其他

- 正位/侧位判据是镜像对称性启发式（实测正位 0.833–0.851、侧位 0.151/−0.049），**不是经过验证的视图分类器**，故仅作软告警。
- 一次检查的多个视图全部保留在 `image_paths`，但 Phase 1 只读第一张；侧位印证未实现。
- 环境中 torch 2.2.2 与 numpy 2.x 存在 ABI 冲突，`readers/cnn.py` 以 `torch.frombuffer` 绕开，升级 torch 后可移除该绕行（见文件内注释）。
